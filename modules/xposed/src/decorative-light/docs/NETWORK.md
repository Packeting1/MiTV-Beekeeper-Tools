# 网络灯控

入口：「炫彩灯」→「网络灯控」。灯珠数量由刷写标记决定：原厂 MCU 为 1，自定义 MCU 为 24，不会读取 MCU 闪存识别。

## 协议

| 协议 | 端口 | 数据映射 |
| --- | --- | --- |
| DDP | UDP 4048 | RGB24，目标 ID 1，偏移 0 为第一颗灯珠 |
| E1.31 / sACN | UDP 5568 | 起始码 0，从所选 Universe 的起始通道连续排列 RGB |

sACN 默认 Universe 1、起始通道 1。1 灯珠占 3 个通道（起始通道 1–510），24 灯珠占 72 个通道（1–441）。

## OpenRGB

添加 DDP 设备，IP 填设置页显示的地址，端口 4048，原厂 MCU 设 1 LED，自定义 MCU 设 24 LEDs，保活间隔 1000 ms。

- 支持 DDP RGB 数据类型 0、1、0x0B。
- 来源、序号（非零）、偏移和 RGB 都相同的 PUSH 包视为保活，避免静态颜色超时；序号更旧且数据变化的包丢弃。
- 原厂 MCU 也能收 24 LED 数据，但只取第一组 RGB。

## 接管与恢复

收到有效数据后，暂停原厂灯效定时器，由 root 进程通过 I2C 输出。原厂模式只发 6 字节帧 `81 01 R G B XOR`，自定义模式只发 75 字节帧 `81 0C RGB×24 XOR`，输出程序都不接受 MCU 升级命令。

- 输出上限约 24 帧/秒，中间帧合并。
- DDP 按偏移拼接，收到 PUSH 时提交；sACN 按 CID、序号和优先级筛选。
- 约 3 秒无数据，恢复本地颜色和光效。
- 手动改颜色、光效、屏幕同色或灯光开关，会退出网络接管。
- 有未完成的 MCU 刷写记录时暂停输出，见 [MCU 固件管理](MCU.md)。

## 限制

- 建议单播。sACN 组播已订阅，但跨设备组播未验证。
- 未实现 sACN 多源 HTP、同步和发现、非零起始码、DDP 查询、RGBW。
- 未验证重启恢复和断电故障。
- UDP 无身份认证，仅限可信局域网，不要转发到公网。
